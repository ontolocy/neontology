# Development

## Setup

This project uses uv for development.

```bash
uv sync --all-extras
uv build
```

`--all-extras` is required, not optional: `tests/conftest.py` imports `NetworkxConfig` at module level, so without the `grand` extra the whole suite fails during collection - even when running against Neo4j or Memgraph only.

## Databases for development and testing

`docker-compose.yml` provides four services: `neo4j` and `memgraph` for development, and `testneo4j` and `testmemgraph` for the test suite. Copy `.env.example` to `.env` first - the compose file reads credentials from it and refuses to start without them.

```bash
docker compose up -d testneo4j testmemgraph    # databases the test suite uses
docker compose up -d neo4j memgraph            # databases for development
docker compose down                            # stop everything
```

The two sets deliberately handle storage differently.

**Development services keep their data** in named volumes (`neontology_neo4j_data` and friends), so a graph survives a restart. To wipe one:

```bash
docker compose down
docker volume rm neontology_neo4j_data         # or: docker compose down -v
```

**Test services keep nothing.** Their data directories are RAM-backed tmpfs mounts, so every start gives a genuinely empty database. This is not a preference: the pytest session fixture asserts the database is empty before it runs, so leftover data causes confusing failures unrelated to the code under test.

Ephemeral storage also avoids a trap worth knowing about, because it applies to the *development* services. Both images only apply the credentials from the environment to an empty data directory. Changing a password in `.env` and restarting therefore appears to do nothing, and connections fail with an authentication error naming credentials that look correct. If that happens, remove the volume:

```bash
docker compose down -v
```

Two smaller notes. Memgraph's tmpfs mounts specify `uid`/`gid` because the server refuses to start unless its data directory is owned by the user it runs as, and tmpfs mounts are root-owned by default. The Neo4j healthcheck is currently broken - the image has no `curl` - so those containers report `unhealthy` while working perfectly; nothing depends on the healthcheck, but do not trust it as a readiness signal.

## Testing

Pytest is used for testing.

Run all the tests (stopping as soon as something fails):

```bash
uv run pytest -x
```

Many of the tests require access to a database instance. These are identified with the 'uses_graph' mark. We can skip these tests like this:

```bash
uv run pytest -m "not uses_graph"
```

Tests are run against the different supported graph engines. You can use `-k` to run against a specific engine only:

```bash
uv run pytest -k 'networkx-engine'     # only run against the networkx engine
uv run pytest -k 'memgraph-engine'     # only run against the memgraph engine
uv run pytest -k 'not neo4j-engine'        # don't run against Neo4j
```

A small subset of tests include benchmarking (with [pytest-benchmark](https://pytest-benchmark.readthedocs.io/en/latest/usage.html)). Running these tests can be controlled with:

`--benchmark-skip` - Skip running any tests that contain benchmarks. Note that this does not run the test bodies at all, so failures in those tests are invisible - prefer `--benchmark-disable` unless you specifically want them skipped.

`--benchmark-disable` - Disable benchmarks. Benchmarked functions are only ran once and no stats are reported. Use this if you want to run the test but don’t do any benchmarking.

`--benchmark-only` - Only run benchmarks.

CI runs with `--benchmark-disable`, so benchmarked tests are exercised for correctness on every run without paying for the timing.

Check coverage with:

```bash
uv run pytest --cov=src/neontology
uv run pytest --cov=src/neontology --cov-report=html
```

Generated report is at `htmlcov/index.html` or view as a locally hosted version:

```bash
python -m http.server --directory htmlcov
```

## Linting and Formatting

Use ruff:

```bash
uv run ruff check src tests
uv run ruff check --fix src tests
uv run ruff format --check --diff src tests
uv run ruff format src tests
```

Tests are linted for real problems - unused imports, undefined names, style - but `tests/**` ignores the docstring (`D`) rules, since a test's name is its documentation.

## Documentation

The documentation is built with mkdocs.

```bash
uv run mkdocs serve    # see how the docs look during development
uv run mkdocs build    # generate the documentation as a static html site
```

## Release

Increment the version, push to Github and upload to pypi!

```bash
git tag va.b.c
git push origin va.b.c # triggers the github action to build & upload to pypi
```
